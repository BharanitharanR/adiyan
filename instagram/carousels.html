The idea

Underneath, it's a mesh, not one bot.

Modular by design. Each agent does one job well, an orchestrator routes every conversation to whichever one actually knows how to help. Memory on two timescales: the recent thread, and a longer-term knowledge base it can search and cite back from.

Building in public

Tonight, Adiyan started spamming itself.

A real incident, from a few hours ago. Here's exactly what happened, and what we shipped because of it.

What we found

5 overlapping scheduled jobs. One of them firing hourly.

A literal duplicate ("Journal" and "Journal Reminder," same job, twice), plus a "check in on patterns" job running every single hour with nothing real to report. Each one, when it had nothing to say, still tried to say something.

AdiyanSwipe →
2 / 5

The actual bug

When a job has nothing to report, it should say nothing.

Instead, the fallback prompt asked for "a warm reminder message" about a description with zero real content. The model reached for template phrasing, "Hi [Name]!", and never had a name to fill in. Every fallback message was a small hallucination in disguise.

Hi [Name]! Just a gentle nudge to check in... 😊

3 / 5

What shipped

Cut the noise. Then fixed the root cause.

Deleted the duplicate, dropped the hourly job to daily, and found a second real bug along the way: a lookup function silently broken for anything but exact-schedule matches. Fixed and shipped. Now, if there's nothing real to say, the message just doesn't send.

4 / 5

The actual lesson

Silence is a valid answer. Fake warmth isn't.

Whether it's a scheduled nudge or an answer to a real question, an AI that admits "nothing here" is more trustworthy than one that always has something to say. That's the standard we're building Adiyan to.
