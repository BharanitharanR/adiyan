Designing memory determinism into a live multi-agent system

A running WhatsApp AI agent mesh had a real, evidenced bug: two different people were sharing one memory bucket. This walks through the design reasoning end to end - from root-causing the bug, to the access-control model it implied, to the architecture decision that model forced, to a phased build where every layer is provable in isolation before the next one is trusted.

System Adiyan - an A2A-protocol multi-agent mesh (orchestrator + specialist agents) behind WhatsApp Scope of this piece Phases 1-2 of a 5-phase rollout, both built and verified live
Every claim on this page is grounded in something actually run this session - a log grep, a live query against real migrated data, or a test executed against a real Neo4j instance - not an assumption about what "should" happen. That discipline is itself part of the design approach worth naming in an interview.
